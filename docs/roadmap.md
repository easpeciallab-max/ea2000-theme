## 1) จุดที่สองแผนขัดกันหรือทำงานซ้ำ · พร้อมคำตัดสิน

### C1 · สองแผนแตะหน้าเดียวกันในสัปดาห์เดียวกันโดยไม่รู้กัน (ปัญหาใหญ่ที่สุด)
แผนคอนเทนต์ W2 สั่งเขียน `/how-to-install/` ใหม่ 1,800 ถึง 2,500 คำ พร้อมภาพจริง 6 ขั้น · แผนดีไซน์ขั้น 5 สั่งรื้อ `/how-to-install/` เป็น stepper 2 คอลัมน์ มี rail ใหม่ ลบ `max-width: 860px` เพิ่ม setting `inst_step{1..6}_time/note` · เช่นเดียวกัน W4 กับ W5 ของแผนคอนเทนต์ (เขียน backtest, risk, forward, pricing ใหม่) ชนกับแผนดีไซน์ขั้น 2, 3, 4, 6 ตรง ๆ

**คำตัดสิน**: เลิกคิดเป็น "งานเนื้อหา" กับ "งานดีไซน์" · คิดเป็น **หน่วยต่อหน้า** หนึ่งหน้าจบในคราวเดียว = โครง + เนื้อหา + ภาพ + schema + ตรวจรับ · ห้ามเขียนเนื้อหาลงในโครงที่กำลังจะเปลี่ยน เพราะจะต้องจัดย่อหน้าใหม่และถ่ายภาพซ้ำ

### C3 · ผังปุ่ม LINE ขัดกันจริง
วัดแล้ว: หน้าแรกมีลิงก์ `lin.ee` **9 จุด** · แผนดีไซน์จะตัดเหลือ 3 · แผนคอนเทนต์วาง GA4 event 4 ตำแหน่ง (`hero`, `pricing`, `footer`, `go`) และบังคับให้ทุกบทความลิงก์ `/go/` ท้ายเรื่อง

**คำตัดสิน · ผังสุดท้าย** (ล็อกก่อนเขียน GA4):
- เดสก์ท็อป: hero · mid-cta · footer-cta · ปุ่มลอย = 4 จุด
- มือถือ: hero · mid-cta · footer-cta · บาร์ล่าง = 4 จุด · **ปิดปุ่มลอยบนมือถือ** เพราะซ้อนกับบาร์ล่าง
- ตัด `.section.cta#cta` ของหน้าแรกทิ้ง (ติดกับ footer-cta เป็นพืด)
- ทุกปุ่มใส่ `data-line-pos` ค่าเดียวกับชื่อ event ไม่ต้องเดาจาก CSS selector

### C4 · เจ้าของ schema ชนกัน
แผนคอนเทนต์ 0.2 ให้ Yoast ออก Organization + sameAs · 0.3 ให้ปลดล็อกธีมให้ออก `SoftwareApplication` · แล้วยังอยากได้ HowTo, FAQPage, Article, Person · แผนดีไซน์ไม่พูดถึง schema เลยทั้งที่กำลังย้ายเนื้อหาที่ schema อ้างถึง

**คำตัดสิน · ทะเบียนเจ้าของ node เขียนไว้ในโค้ดคอมเมนต์**
- Yoast: `Organization`, `WebSite`, `WebPage`, `BreadcrumbList`, `Article`, `Person`
- ธีม: `SoftwareApplication` เท่านั้น · และ `HowTo` + `FAQPage` (เพราะเนื้อหามาจาก Customizer ไม่ใช่บล็อก Yoast จึงออกให้ไม่ได้)
- ห้ามมี `WebPage` สอง node · ตรวจด้วย Rich Results Test ทุกครั้งหลัง deploy

### C5 · `hero_title` ถูกใช้สองหน้าที่ · เป็นข้อขัดแย้งที่แผนคอนเทนต์มองข้าม
แผนคอนเทนต์ 2.1 เสนอ H1 ยาว 42 อักขระ (`EA2000 · EA เทรดทอง XAUUSD บน MetaTrader 5`) แล้วเขียนว่า "ค่านี้เป็นชื่อใน SoftwareApplication ด้วย ซึ่งเป็นสิ่งที่ต้องการ" · **ไม่ใช่สิ่งที่ต้องการ** ชื่อผลิตภัณฑ์ใน schema ต้องเป็น `EA2000` ล้วน ไม่ใช่ประโยคโฆษณา

**คำตัดสิน**: เพิ่ม setting `product_name` (ค่าเริ่มต้น `EA2000`) ให้ schema ใช้ · `hero_title` เหลือหน้าที่เดียวคือ H1

### C6 · ข้อเท็จจริงที่แผนดีไซน์ผิด (แก้แล้ว)
- แผนดีไซน์กังวลว่า Cloudflare จะค้าง `style.css` · **ไม่จริง** ธีมใส่ `filemtime()` ให้ทั้ง style.css และ main.js อยู่แล้ว (`functions.php:54-55`) และตรวจสดได้ `?ver=1788784965` · ปัญหาแคชค้างมีเฉพาะ **รูปในธีม** ที่อ้างตรงจาก URL
- แผนดีไซน์ประเมิน GTranslate JS ที่ 6.7 KB · **วัดจริง 23.1 KB**
- แผนดีไซน์กังวลว่า `/go/` อาจไม่ได้ head ของ Yoast · **ตรวจแล้วได้** (`<title>ติดต่อและลิงก์รวม EA2000 - EA2000</title>` และ meta noindex ของ Yoast อยู่ครบ) แผนคอนเทนต์ 2.7 ใช้งานได้จริง

### C7 · กำลังการผลิตขัดกันแบบคำนวณแล้วไม่พอ
แผนคอนเทนต์ตั้งบนสมมติฐาน 4 ถึง 6 ชั่วโมงต่อสัปดาห์ แล้วสั่ง: 20 บทความ + เขียนใหม่ 8 หน้า + 2 คลิป YouTube + ตั้ง GA4/GSC · แผนดีไซน์เพิ่มงานธีมอีกราว 5.5 วัน ซึ่ง **ไม่มีอยู่ในปฏิทิน 90 วันเลยแม้แต่ช่องเดียว**

**คำตัดสิน**: ลดเป้า 90 วันเหลือ **10 บทความ** และใส่งานธีมลงปฏิทินจริง · 20 บทความคือแผนของทีม 2 ถึง 3 คน ไม่ใช่คนเดียวที่ต้องถ่ายภาพ MT5 เองด้วย

### C8 · GTranslate ค้างอยู่ระหว่างสองแผน
แผนดีไซน์บอก "ควรถามเจ้าของก่อนลงแรงทำ dark mode ให้ widget ที่อาจถอดทิ้ง" · แผนคอนเทนต์ 0.13 บอก "ตรวจว่าไม่สร้าง URL แปลที่ index ได้" · ไม่มีใครตัดสิน

**คำตัดสิน**: **ถอดทิ้ง** เว็บภาษาไทยล้วน กลุ่มเป้าหมายเป็นเทรดเดอร์ไทย conversion คือแชท LINE ภาษาไทย · ประหยัด JS 23 KB + CSS `!important` 130 บรรทัดเดิม + 40 บรรทัดใหม่ที่ยังไม่ต้องเขียน

### C9 · หน้าที่ไม่มีข้อมูลได้แรงงานมากที่สุด
แผนดีไซน์ทุ่ม 2 วันเต็ม (ขั้น 3 และ 4) ให้ `/backtest/` และ `/forward-test/` ซึ่งเป็นสองหน้าที่ **ไม่มีข้อมูลจริงแม้แต่ตัวเลขเดียว** · แผนคอนเทนต์ก็ตั้งคีย์เวิร์ดให้สองหน้านี้ใน W4-W5

**คำตัดสิน**: เลื่อนไปเฟสสุดท้าย · และระหว่างนี้ตั้ง `noindex` **รายหน้า** ให้สองหน้านี้ พร้อมเอาออกจากเมนูหลัก · หน้าเปล่าบนเว็บ YMYL เป็นภาระ ไม่ใช่ทรัพย์สิน

### C10 · `/articles/` ถูกวางเป็น hub ทั้งที่ยังไม่มีอะไร
วัดแล้ว: `/articles/` มีบทความ **0 ชิ้น** และ **ไม่ปรากฏใน sitemap ใดเลย** (`page-sitemap.xml` ไม่มี เพราะเป็น posts page · `post-sitemap.xml` ไม่มี เพราะ 0 โพสต์)

**คำตัดสิน**: อย่าเพิ่งลงแรงกับ `/articles/` จนกว่าจะมีบทความ 3 ชิ้น · ก่อนหน้านั้นให้เอาออกจากเมนูหลัก

## 2) สิ่งที่ทั้งสองแผนพลาด · พร้อมหลักฐานที่วัดวันนี้

### M1 · เว็บยัง noindex จริง และไม่มีใครกำหนด "เงื่อนไขปลด"
ยืนยันสด: `content='noindex, nofollow'` ทุกหน้า · แผนคอนเทนต์วางไว้ที่ W3 ของปฏิทิน 13 สัปดาห์ ซึ่งช้าเกินไปโดยไม่มีเหตุผล เพราะการ index ใช้เวลาเดินของมันเองอีกหลายสัปดาห์ · **การปลด noindex ต้องเป็นเงื่อนไข ไม่ใช่วันที่** และเงื่อนไขที่จำเป็นจริงมีแค่ 4 ข้อ ซึ่งใช้เวลา 2 ถึง 3 วัน ไม่ใช่ 3 สัปดาห์ (ดูเฟส 2)

### M2 · sitemap ปัจจุบันมีหน้าเก่าของ EA Special อยู่แล้ว · นี่คือระเบิดเวลา
ดึง `page-sitemap.xml` สดวันนี้ได้ 12 URL ซึ่งรวม:
```
/results/  /guides/  /risk-warning/   (ทั้งสามเป็นของ EA Special · ยัง publish · HTTP 200)
```
และ `/risk-warning/` มี `<title>คำเตือนความเสี่ยง - EA2000</title>` ซึ่ง **ซ้ำกับ `/risk-disclosure/` แทบทุกประการ** · วินาทีที่ปลด noindex Google จะได้ sitemap ที่มีหน้าคำเตือนความเสี่ยงสองหน้าแข่งกันเอง บวกหน้าเปล่าอีกสองหน้า · แผนคอนเทนต์เขียนเรื่องนี้ไว้ที่ข้อ 0.8 ว่า "เจ้าของตัดสินใจ" ซึ่งไม่ใช่แผน · **ต้องจบก่อนปลด noindex ไม่ใช่หลัง**

`/privacy-policy/` ยังเป็นข้อความ default ภาษาอังกฤษของ WordPress (นับคำว่า suggested text / personal data ได้ 14 ครั้ง) และอยู่ใน sitemap ด้วย

### M3 · 0 บทความ แปลว่า `single.php` ไม่เคยถูกเรนเดอร์บนเว็บจริงเลย
ทั้งสองแผนพูดถึงบทความ 20 ชิ้นโดยไม่มีใครสังเกตว่า reading progress, TOC, ปุ่มแชร์, related rail, `ea2000_get_post_views()` และ `post-sitemap.xml` **ยังไม่เคยทำงานจริงสักครั้ง** · การเผยแพร่บทความชิ้นแรกอาจเจอบั๊กเทมเพลตที่ไม่มีใครรู้

**สิ่งที่ขาด**: บทความทดสอบ 1 ชิ้นที่เป็นของจริง (ไม่ใช่ lorem) เผยแพร่ก่อนเริ่มปฏิทิน เพื่อเปิดเผยบั๊กและสร้าง author entity + post-sitemap · แนะนำใช้ `A1 · autotrading disabled by server` เพราะเป็นบทความที่คู่แข่งภาษาไทยเป็นศูนย์ และเขียนได้โดยไม่ต้องอ้างผลงานใด ๆ

### M4 · ไม่มีผลเทรดจริง แต่ไม่มีใครสั่ง noindex หน้าเปล่า
ทั้งสองแผนยอมรับว่าไม่มีข้อมูล แล้วก็เดินหน้าเขียน title, meta, keyword และโครงหน้าให้สองหน้านั้นต่อ · สิ่งที่ควรทำคือ **ตั้ง noindex รายหน้าใน Yoast ให้ `/backtest/` และ `/forward-test/`** จนกว่าจะมีรายงานจริง · เพิ่มข้อความสถานะตามที่แผนคอนเทนต์เสนอไว้แล้ว (ซึ่งเขียนไว้ดี) แต่ไม่ให้ Google เห็นหน้าเปล่า

### M5 · ปัญหาความเร็วตัวจริงไม่มีในแผนไหนเลย · นี่คือของถูกที่สุดที่ได้ผลมากที่สุด

### M6 · PHPSESSID ทำให้แคชถูกข้ามทุก request · และแผนไหนก็ไม่โยงว่าใครเป็นคนตั้ง
ยืนยันสด: `Set-Cookie: PHPSESSID=...` · `x-cache-status: BYPASS` · `cf-cache-status: DYNAMIC` · `Cache-Control: no-store, no-cache, must-revalidate` · TTFB วัด 3 ครั้งได้ 0.298 / 0.290 / 0.293 วินาที คงที่ = ไปถึง PHP ทุกครั้งจริง

ผู้ต้องสงสัยอันดับหนึ่งคือ PixelYourSite (เป็นปลั๊กอินเดียวที่มีเหตุผลต้องใช้ session) · **การถอด PixelYourSite จึงแก้สามเรื่องพร้อมกัน: JS 369 KB + jQuery 101 KB + แคชกลับมาทำงาน** · นี่คืองานที่คุ้มที่สุดในเอกสารทั้งสองฉบับ และไม่มีใครเขียนถึง

### M7 · แคช Cloudflare · แก้ข้อเท็จจริงและระบุขอบเขตให้ถูก
`style.css` และ `main.js` มี `filemtime()` แล้ว จึงปลอดภัย · ที่ยังเสี่ยงคือ **รูปในโฟลเดอร์ธีม** ซึ่งอ้างตรงจาก URL ไม่มี query · กฎที่ต้องเขียนไว้ให้ชัด: **เปลี่ยนรูปในธีม = เปลี่ยนชื่อไฟล์เสมอ** และ purge Cloudflare หลัง deploy ทุกครั้ง · และยังค้างงานเดิมจาก CLAUDE.md: หลัง deploy commit `b0c039c` ต้องส่ง `{"links_fast_img":null,"links_feature_img":null}` ไปที่ `ea2000/v1/mods` เพื่อกลับไปใช้ default ชื่อใหม่ · **ไม่มีในแผนไหนเลย**

### M8 · การ deploy ยังเป็นมือ และไม่มีทางถอย
WP Pusher "Update theme" ไม่เขียนไฟล์เพราะไม่มี GitHub token · วิธีปัจจุบันคืออัปโหลด zip ทับผ่าน Themes > Add > Upload > Replace · แผนดีไซน์แก้ `style.css` เกือบ 90 กฎ และแตะเทมเพลต 10 ไฟล์ แต่ไม่มีขั้นตอน deploy, ไม่มี backup, ไม่มี rollback, ไม่มี staging · **การอัปโหลด zip ที่ผิดพลาดทำให้เว็บล่ม และไม่มีใครเตรียมไฟล์ zip ตัวก่อนหน้าไว้**

### M9 · เศษซากของ EA Special ที่ยังไม่มีใครเก็บ
- ธีม EA Special ยังติดตั้งอยู่ (ไม่ active) = พื้นผิวอัปเดตและความปลอดภัยที่ไม่จำเป็น
- เมนูเก่า id 4 และ 5 ยังอยู่
- หน้า `/about/` เป็น draft (วันนี้คืน 404) ทั้งที่แผนคอนเทนต์บอกว่าเป็นสัญญาณ E-E-A-T ที่ขาดมากที่สุด
- Yoast title template ระดับเว็บยังเป็นของ EA Special ตาม CLAUDE.md → **โพสต์ใหม่ทุกชิ้นจะสืบทอด title ผิด** และไม่มีในแผนไหน
- breadcrumb ยังเขียนว่า "Home" ไม่ใช่ "หน้าแรก" (ค้างจาก CLAUDE.md ขั้น 6)
- `Tested up to: 6.8` ใน style.css แต่เว็บรัน WP 7.1

### M10 · ไม่มีเอกสารกฎหมายฝั่งขาย
มี Privacy (ภาษาอังกฤษ default) และ Data deletion · **ไม่มีเงื่อนไขการใช้งาน ไม่มีนโยบายคืนเงิน ไม่มีการระบุตัวตนผู้ขาย** · เว็บกำลังจะรับเงินหลักพันจากผู้บริโภคไทย · ผู้ขายออนไลน์ในไทยมีหน้าที่ระบุตัวตนผู้ขายและช่องทางติดต่อ และการขายออนไลน์เชิงพาณิชย์อาจต้องจดทะเบียนพาณิชย์อิเล็กทรอนิกส์ · **ผมไม่ใช่ที่ปรึกษากฎหมาย เจ้าของต้องตรวจกับผู้รู้** แต่การเปิด index โดยไม่มีสามเอกสารนี้เป็นความเสี่ยงที่ทั้งสองแผนไม่ได้พูดถึง

### M11 · ไม่มีแผนหาลูกค้าระหว่างรอ SEO · ธุรกิจรอ 6 เดือนไม่ได้
เว็บใหม่ + noindex + 0 บทความ = organic แทบเป็นศูนย์อย่างน้อย 3 เดือน (แผนคอนเทนต์เองก็ยอมรับ: เดือนแรก `line_click` เป้า 0 ถึง 3 ครั้ง) · ทั้งสองแผนไม่มีคำว่า "แล้วเดือนที่ 1 ถึง 3 ขายยังไง"

**สิ่งที่ขาด**: ช่องทางที่ให้ผลทันทีและใช้ของที่มีอยู่แล้ว: LINE OA broadcast, OpenChat ที่ตั้งไว้แล้ว, คลิป YouTube 2 คลิปที่แผนคอนเทนต์วางไว้ที่ W9-W11 **ควรเลื่อนมาต้นทาง** เพราะเป็นทั้งช่องทางขายและสัญญาณ E-E-A-T ในเวลาเดียวกัน

### M12 · ตัวชี้วัด conversion ที่วางไว้วัดผิดสิ่ง
`line_click` นับ "คลิก" ไม่ใช่ "แชท" · และเมื่อผู้ใช้เข้าไปใน LINE แล้ว ไม่มีทางรู้เลยว่าเขามาจากหน้าไหน · แผนคอนเทนต์แยก event ตามตำแหน่งปุ่มได้ แต่แยกไม่ได้ว่าคลิกไหนกลายเป็นแชท

**สิ่งที่ขาด**: ข้อความต้อนรับใน LINE OA ที่ถามสั้น ๆ ว่า "ทราบจากช่องทางไหน" หรือใช้ `/go/` เป็นทางผ่านเดียวที่ติด UTM · ต้นทุนแทบเป็นศูนย์ แต่เป็นข้อมูลเดียวที่บอกได้ว่าคลัสเตอร์ไหนสร้างยอด

### M13 · รายละเอียดเล็กที่หลุดทั้งคู่
- **alt text**: หน้าแรกมีรูป 6 ใบ **alt ว่าง 3 ใบ** · เว็บที่วางเดิมพันไว้ที่ "ชนะด้วยภาพหน้าจอ" ต้องมี alt ทุกใบ ทั้งเพื่อ accessibility และ image search
- **`.reveal { opacity: 0 }` ไม่มี no-js fallback** · แผนดีไซน์ระบุเป็นความเสี่ยงข้อ 6 แต่ไม่ได้ใส่ลงตารางงาน · แก้ 2 บรรทัด ควรอยู่เฟสแรก
- **ไม่มี baseline ความเร็วก่อนรีดีไซน์** จึงพิสูจน์ไม่ได้ว่ารีดีไซน์ทำให้ดีขึ้นหรือแย่ลง · ตัวเลขในข้อ M5 ใช้เป็น baseline ได้เลย
- **`/go/` จะสวนทางกับทั้งเว็บถาวร** เพราะไม่เรียก `get_header()`/`get_footer()` จึงไม่ได้ token โทนมืด · แผนดีไซน์บอกว่า "ไม่แตะ ซึ่งถูกแล้ว" แต่ไม่ได้ตัดสินว่าเจ้าของยอมรับไหมที่หน้าติดต่อจะหน้าตาไม่เหมือนเว็บ

### M14 · ภาระ setting ใหม่ 30 ตัวไม่ถูกนับเป็นเวลาของเจ้าของ
แผนดีไซน์เสนอ Customizer setting ใหม่กว่า 30 ตัว ส่วนใหญ่เป็น textarea ที่ต้องกรอกเอง · แต่ละช่องว่างคือเวลาเจ้าของ · **เพิ่มเฉพาะ setting ที่จะมีเนื้อหาจริงภายใน 90 วัน** · ทุกตัวที่ขึ้นต้นด้วย `bt_` และ `fw_` เลื่อนไปเฟสสุดท้ายพร้อมข้อมูลจริง

## สรุปคำตัดสินสั้นที่สุด

1. **ถอด PixelYourSite** คือการกระทำเดียวที่คุ้มที่สุดในทั้งสองแผนรวมกัน: ตัด JS 470 KB และปลดล็อกแคช Cloudflare ที่ถูกข้ามทุก request อยู่ตอนนี้ · ไม่มีอยู่ในแผนไหนเลย
2. **จัดการหน้าเก่า 3 หน้าให้จบก่อนปลด noindex** เพราะ sitemap วันนี้แจกหน้าคำเตือนความเสี่ยงซ้ำสองหน้าและหน้าเปล่าอีกสอง
3. **ปลด noindex ที่ปลายเฟส 1 ไม่ใช่ W3** เงื่อนไขที่จำเป็นจริงใช้เวลา 2 ถึง 3 วัน และการ index ใช้เวลาเดินของมันเองอีกหลายสัปดาห์
4. **เลิกแยกงานเนื้อหากับงานดีไซน์** ทำเป็นหน่วยต่อหน้า · เริ่มที่ `/how-to-install/` และจบที่ `/backtest/` กับ `/forward-test/` ซึ่งเป็นหน้าที่ยังไม่มีข้อมูล
